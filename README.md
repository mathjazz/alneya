# Alneya — website

Bilingual (English / Slovenian) static site for **Alneya — Soul Decoder & Healer**.
Plain HTML, CSS and JS, generated by a small dependency-free Node script and
served from GitHub Pages.

```
npm run build        # light theme  → dist/
npm run build:green  # green theme  → dist-green/
npm run build:both   # both
npm run serve        # preview dist/       at http://localhost:4321
npm run serve:green  # preview dist-green/ at http://localhost:4322
```

Node 18 or newer. There are no dependencies to install.

## Where things live

```
src/
  layout.html            page shell: <head>, header, footer, scripts
  pages/*.html           one template per page, shared by both languages
  partials/*.html        header, footer, press strip, newsletter, icon sprite…
  partials/logo-mark.svg the crescent-and-eye mark, redrawn as vector
  locales/en.json        ALL English copy
  locales/sl.json        ALL Slovenian copy
  assets/css/site.css    the whole design system
  assets/js/site.js      mobile nav, library filters, scroll reveal
  assets/img/            photographs, favicon
build.js                 the generator
serve.js                 local preview server
dist/                    generated — never edit, never commit
```

**To change wording, edit the locale JSON files — not the HTML.** The templates
contain no English or Slovenian text at all, so every string has exactly one
home and the two languages can never silently drift apart.

## How the two languages work

Each page is written once and rendered twice:

| Page           | English            | Slovenian            |
| -------------- | ------------------ | -------------------- |
| Home           | `/`                | `/sl/`               |
| About          | `/about/`          | `/sl/o-meni/`        |
| Work with me   | `/work-with-me/`   | `/sl/sodelujva/`     |
| Client stories | `/client-stories/` | `/sl/zgodbe-strank/` |
| Library        | `/library/`        | `/sl/knjiznica/`     |
| Contact        | `/contact/`        | `/sl/kontakt/`       |

Slugs are localised — they come from the `slugs` block at the top of each locale
file, so renaming a Slovenian URL is a one-line change. Every page gets the
correct `<html lang>`, a canonical URL, `hreflang` alternates with an
`x-default`, and an entry in `sitemap.xml`. The language switcher in the header
always links to the *same page* in the other language, not to the home page.

### A note on the Slovenian copy

Slovenian forces a grammatical gender on second-person address. The translation
currently uses **feminine forms** throughout (`postani to, kar si bila`), which
matches the English copy's "I help women…". If Alneja wants to address men too,
those forms need revisiting — it is a handful of lines, mostly in
`home.hero.*`, `home.pain.*`, `home.promise.*` and `about.*`. Note she now works
in five languages (English, German, Hungarian, Croatian, Slovenian) — only two of
them are on the site, so a German or Croatian visitor still lands in English.

## Templating cheatsheet

| Syntax | Meaning |
| --- | --- |
| `{{ a.b }}` | insert a value, HTML-escaped |
| `{{{ a.b }}}` | insert a value as raw HTML (used for `<br>` and `<em>` in copy) |
| `{{> name }}` | include `src/partials/name.html` or `.svg` |
| `{{#each a.b}} … {{/each}}` | loop a list; inside, `{{ .field }}` is the current item, `{{ @number }}` is `01`, `02`… |
| `{{#if a.b}} … {{else}} … {{/if}}` | conditional |
| `{{ @nav.about.url }}` | the About URL in the current language |
| `{{ @alternates }}`, `{{ @year }}`, `{{ @assets }}` | build-provided values |

Any key that is missing from a locale file is reported by name when you build,
so a half-finished translation cannot ship silently.

## Eleven themes, nine palettes

A theme is a **palette** file, optionally plus one shared **structure** file.
Not every palette has every version — only the ones worth comparing.

| Palette | Light | Dark | Painted |
| --- | --- | --- | --- |
| **plum — the live design** | — | — | `build:plum` → `:4331` |
| amethyst + lavender (default) | `build` → `:4321` | — | — |
| deep moss + beige | — | `build:green` → `:4322` | — |
| soft eucalyptus | `build:sage` → `:4323` | `build:sage-deep` → `:4324` | — |
| amethyst + antique gold | `build:violet` → `:4325` | `build:violet-deep` → `:4326` | — |
| soft wisteria | — | `build:lavender` → `:4327` | — |
| Baumit Life 1033, soft sage green | — | — | `build:baumit-1033` → `:4328` |
| Baumit Life 1023, olive green | — | — | `build:baumit-1023` → `:4329` |
| Baumit Life 0674, dusty mauve | — | — | `build:baumit-0674` → `:4330` |

**`theme-plum.css`** — the live design, and the only one with its own
typography: Cormorant Garamond over DM Sans rather than Fraunces over
Montserrat. Four plum bands (header, hero, thread, final — plus the story and
testimonials) alternate with mist and white. It keeps the baumit-0674 mauve
`#ab95ac` as an accent rather than a ground.

The other two structure files differ only in which way the text runs.

**`theme-dark.css`** — the header, hero, Unblock Method section, testimonials
and footer join one near-black band
(`linear-gradient(160deg, --deep-800, --deep-900)` plus a `--deep-700` radial
lift), with **light** text on it.

**`theme-paint.css`** — the same six surfaces, but the band is the paint colour
itself and the text on it is **dark**. This exists because a Baumit paint is a
mid-tone: white on it only reaches ~2.7:1, well under AA. The paint is the
darkest colour on the page, the header sits one shade deeper so it reads as its
own surface, and `--band-ink` / `--band-ink-soft` / `--band-accent` carry the
type.

```
src/assets/css/
  theme-tokens-green.css        palette only
  theme-tokens-sage.css         palette only
  theme-tokens-violet.css       palette only
  theme-tokens-lavender.css     palette only
  theme-tokens-baumit-1033.css  palette only, generated from the paint colour
  theme-tokens-baumit-1023.css  palette only, generated from the paint colour
  theme-tokens-baumit-0674.css  palette only, generated from the paint colour
  theme-tokens-plum.css         palette + the Cormorant/DM Sans pairing
  theme-dark.css                near-black bands, light text; palette-agnostic
  theme-paint.css               mid-tone bands, dark text; palette-agnostic
  theme-plum.css                the live design; plum bands, own type scale
```

`npm run build:all` builds all eleven. A new palette is one file plus one line
in the `THEMES` map in `build.js`.

The three Baumit palettes are **generated**, not hand-picked: each takes the
paint's hex from baumit.si, converts it to a hue, and derives grounds, deep
shades and inks from one shared lightness/saturation recipe. That is why they
feel like one family despite coming from different hues — and why the
contrast numbers come out consistent. To add another paint colour, copy the
generator block and give it the new hex.

One thing to know before tuning them: with **dark** text, the *darkest* stop of
a gradient is the worst case, not the lightest. The band inks are therefore
solved against `--deep-900`, so they clear AA everywhere the paint appears. A
mid-tone also caps the achievable contrast at roughly 5.9:1, which leaves no
room for a lightness hierarchy — headings sit at the floor, body text at the
AA line, and the rest of the hierarchy comes from weight and size.

### Browser chrome

Each theme declares a `<meta name="theme-color">` matching its header, so
Safari tints its toolbar (and iOS its status bar) to match the site. The
colours live in `THEME_COLORS` in `build.js` — **keep them in step with each
palette's `--deep-800`**, or `--ivory` for the light-header themes.

The dark header also sets `background-color` *as well as* its gradient. Safari
falls back to sampling the page's solid colour, and a bare gradient leaves
that transparent, which silently loses the tint.

### Contrast

Every text-and-background pair is checked against WCAG AA (4.5:1, or 3:1 for
large text) in all ten themes. Several tokens — `--gold-600`, `--gold-700`,
`--ink-faint`, and sage's `--deep-300` — were darkened specifically to clear
it. **If you change a palette, re-check.**

One known failure is left deliberately: white button text on the gold gradient
measures **2.4–3.2:1** in every theme. Fixing it means darkening the gold,
which changes every call to action on the site, so it is a brand decision
rather than a bug fix.

## Design

Light, airy and mystical — the information architecture follows soultribe.media,
the lightness and the photo-led service cards follow reganhillyer.com:

- ivory `#fdfbf8`, shell `#f8f2ea` and blush `#faf0ec` as the default grounds
- lavender `#f5eff9` and sage `#eff3ec` washes for the emotional sections
- warm gold `#a8813c` / `#ebd8ae` for accents, rules, buttons and the ornament
- amethyst `#382a43` used **once per page** — a single deep band plus the footer

The "As seen in" strip renders the seven outlet names as **styled text, not
official logos** — I have no logo files for them. Each is shaped to echo its real
masthead (heavy serif for Brainz, condensed sans for CEO Journal, and so on). To
use real artwork, drop a file into `src/assets/img/` and add
`"logo": "logo-brainz.svg"` to that outlet in `press.outlets`; the template
switches to the image automatically.

Mystical texture comes from two reusable pieces rather than heavy imagery: a
faint gold star field (`--stars`) and a soft radial `.aura` glow behind centred
headings. Sections are separated by their background colour alone — there is no
divider graphic. The icon set is drawn around
sacred symbols — third eye, lotus, tree of life, chakras, seed, north star,
mandala, hamsa, flower of life — in `src/partials/icons.html`.

Type is **Fraunces** (display serif) over **Montserrat** (everything else), the
same pairing as the reference site, loaded from Google Fonts. All colour tokens
are CSS custom properties at the top of `site.css`, so a rebrand is a handful of
lines.

JavaScript is enhancement only. With it disabled you lose the slide-in mobile
menu (the links are still all there), the library category filter (all entries
show) and the fade-in on scroll. Nothing else changes.

## Deploying to GitHub Pages

`.github/workflows/deploy.yml` builds the site and publishes it on every push to
`main`. `dist/` is deliberately **not** committed — the workflow regenerates it.

1. Push this repository to GitHub.
2. **Settings → Pages → Source → GitHub Actions.**
3. **Settings → Pages → Custom domain**, enter `alneya.com` and tick
   **Enforce HTTPS** once the certificate has been issued.
4. Point DNS at GitHub (see below).

The workflow defaults to `SITE_URL=https://alneya.com`, `BASE_URL=/` and
`THEME=plum`, so it needs no configuration. To override any of them
without editing the file, set a repository variable of the same name under
**Settings → Secrets and variables → Actions → Variables**:

- `SITE_URL` — the final address. Used for canonical tags, `hreflang`, the
  sitemap and the generated `CNAME`, so it must be right.
- `BASE_URL` — `/` for a custom domain or a `<user>.github.io` repository;
  `/<repo-name>/` for a project site such as
  `https://mathjazz.github.io/alneya/`. Getting this wrong is the one thing
  that breaks every link and image at once.
- `THEME` — any key from the `THEMES` map in `build.js`. Changing this
  variable and re-running the workflow reskins the live site; no code change.

### DNS for the apex domain

Four `A` records at the zone apex, plus `www` as a `CNAME`:

```
@      A      185.199.108.153
@      A      185.199.109.153
@      A      185.199.110.153
@      A      185.199.111.153
www    CNAME  mathjazz.github.io.
```

IPv6 is optional but harmless — add `AAAA` records for `2606:50c0:8000::153`
through `2606:50c0:8003::153` if the registrar supports them.

`build.js` writes `dist/CNAME` automatically for apex builds, which is what
keeps the custom domain from being cleared on redeploy. It deliberately does
*not* write one when `BASE_URL` is a subpath, so the side-by-side previews
below cannot hijack the domain.

### Side-by-side theme previews

To publish several themes at once (useful while choosing), build each with its
own base path and upload them to sibling folders:

```
SITE_URL=http://horv.at BASE_URL=/alneya/ npm run build
SITE_URL=http://horv.at BASE_URL=/alneya-green/ THEME=green OUT_DIR=dist-green node build.js
```

To build the live site exactly as Actions does, locally:

```
SITE_URL=https://alneya.com BASE_URL=/ THEME=plum npm run build
```
